# Environment variables

The ArchB switch table also constructs runtime environment names from APS5_ARCHB_ and each feature name. APS5_ARCHB_FIX_COMPUTE_SYNC_UNLOCKED=1 enables fence waits without the GPU mutex before compute dispatch label recording; it defaults to off and is sampled once per dispatch. Fence lifetime is retained through the wait. Completion, pending-write publication and the subsequent label readback rescan run under the mutex. Nested waits, resource-build waits and depth-conversion waits retain their locked path. With the recorder enabled, `fix_csync_*` counters report unlocked waits, wait and relock milliseconds, refusals and teardown.

The code reads environment names through `getenv`, `IsEnvironmentSet`, `kibSetting`, `MaskFromEnvironment`, `EnvInt`, `GetEnvironmentVariableA`, `GetEnvironmentVariableW` and `_wgetenv` with a wide literal, `configured`, `PipelineSwitch`, `environmentCount`, `EnvironmentNumber`, `MebibytesFromEnvironment` and `addWideString` (the wide names the Windows entry stub reads). This table lists every `APS5_*` and `ANYPS5_*` name it reads, its kind, the value used when it is unset and what it does, one table per library. Regenerate the names with `python3 tools/env_reference.py --table`; the Conventions check fails when a name the code reads has no row here, or a row's name is no longer read.

### Draw-hit eligibility census

`APS5_ARCHB_DRAW_HIT_CENSUS=1` enables a default-off diagnostic for direct non-indirect vertex-path draw-cache hits. It leaves the ordinary lookup, capture validation and drawing unchanged. An observation is admitted only after exact validation and unchanged fault/stored proofs over its captured ranges, with queued/pending writes, labels, image shadows and mapping changes refused. Later packet/argument/user-word matches are predicted and checked against the ordinary path. Recorder counters `j3_prediction_verified` and `j3_prediction_mismatch` report agreement; `j3_refused_*` reports candidate and admission refusals. `j3_hit_lookup_ns` and `j3_predicted_hit_lookup_ns` measure existing-entry validation elapsed time minus tracked GPU waits (separate `j3_hit_lookup_wait_ns`), excluding key/alias construction, and `j3_hit_prepare_material_ns` measures program-memory/linked-program/ShaderMemory setup. Use with `APS5_ARCHB_RECORDER=1` and the normal write-fault tracking settings; the diagnostic overhead is not a speed measurement.

With the same census switch, `j3_*` phase suffixes split draw prologue, key/relocation, decode/programs, indirect setup, stage assembly, bookkeeping and enqueue preparation. `Shader.J3PrimaryStage`, `Shader.J3VerifyStage`, `Shader.J3MeshRecapture`, `Shader.J3IndirectVerify` and `Shader.J3IndirectRecapture` distinguish capture populations; their `j3_capture_invocation` phase excludes subsequent capture export. Packet early exits become `j3_queued_label`, `j3_queued_dma`, `j3_queued_constant`, `j3_queued_sample` or `j3_satisfied_*`. `J3.EnqueueReclaim` measures retired-item destruction, and `j3b_enqueue_mutex_wait_ns` measures mutex acquisition. `j3b_*` counters count populations. These phases partition existing parent phases, not additional CPU work; queued packet and draw enqueue phases still include waits. Keep `APS5_PROFILE_DRAW` unset so packet fast paths and finisher eligibility stay unchanged.
