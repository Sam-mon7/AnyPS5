# relinker technical debt

### Functional

- [Windows red-zone protection](../../../core/relinker/elfpatcher/src/windows/WindowsRedZonePatcher.cpp) is an experimental relink-time adaptation of shadPS4's GPL-2.0-or-later patcher from Kyty SuperMedo (`src/loader/redZonePatcher.cpp` and `.h`, copyright 2026 shadPS4 Emulator Project). `ANYPS5_RELINK_REDZONE=1`, sampled once per relinker process, enables it for the executable and every converted Windows guest module. Other values and an unset variable leave PE bytes unchanged. Enabled images contain a `.redzone` section beginning with `APS5RZ`, version byte 1, and a reserved zero byte, even when no sites qualify. Output paths are unchanged; use a separate output directory when comparing versions. Linux and macOS outputs do not use this pass.
  Kyty registers each loaded module with an 8 MiB trampoline arena in `runtimeLinker.cpp` before loading segments; after its normal `PatchProgram` instruction rewrites it calls `DecodeEhFrameFunctionStarts` and `PatchRedZoneMemoryInstructions` for the executable file-backed segments, then flushes the instruction caches and unregisters the arena when unloading. AnyPS5 instead emits its trampolines into the PE at relink time. Kyty reads function starts from the version-1 `.eh_frame_hdr` binary-search table, bounds each function by the next start (the final function by its executable segment), walks direct control flow, resolves bounded and scanned relative jump tables, and attempts a validated linear sweep for remaining indirect branches. The jump-table pattern is `lea B,[rip+T]`, `movsxd R,[B+4*I]`, `add R,S`, `jmp R`, where B and S resolve to T. The bounded resolver requires a recognized unsigned `cmp`/`ja` or `jae` guard and at most 4096 entries. The scanned resolver follows predecessor register definitions and copies, scans at most 2048 entries per candidate table, and stops when a target is outside the function or not a validated linear instruction boundary. Sweeping is accepted only when its boundaries agree with the control-flow walk and no RIP operand points to inline data between them. Kyty tracks 128 individual bytes with backward use/definition liveness, translates masks for recognized RSP deltas, and assumes every byte live for escaped red-zone addresses, unknown RSP changes, unresolved branches or missing targets. Non-stack memory accesses, including implicit string accesses, are candidates only while red-zone data is live; LEA, NOP and ordinary stack-relative operands are excluded. A relocated access runs between flag-preserving LEAs lowering and restoring RSP by 128 bytes. MOV RSP from non-stack memory omits the restore. Instructions that also read RSP are refused, rather than rebasing their stack operands; RIP-relative memory and relative branches are rebased to their original targets.
  Kyty also lowers RSP around direct calls while data is live (its TLS rewriter introduces such calls). For an indirect memory call it lowers RSP, saves R11 below the red zone, loads the target into R11, exchanges it with the saved R11, restores RSP, and calls through the saved target below the red zone. This preserves the original callee stack arguments and R11. The actual call retains its original return-address slot: red-zone data live across an ordinary ABI call is not made safe. Five-byte jumps replace instruction-aligned forward or backward spans that do not cross branch entries. Kyty's additional short-jump relay chains and nearby relocated host spans rescue otherwise short sites. Calls, terminating memory branches, RSP-dependent accesses, failed encodings, inaccessible spans and rel32 range failures can remain unprotected. Its `SUPERMEDO.md` reports that enabling the patcher breaks God of War Sons of Sparta; its game measurements do not establish general correctness.
  AnyPS5 uses `X64InstructionDecoder::DecodeInstruction` for lengths, flow and RIP fields, `DecodeMemoryOperand` for ModRM/SIB displacements, and `StubBodyBuilder::MoveControlFlow`, `RipRelative` and `ApplyStubRelocations` for encoding and relocation. Raw LEA/push/XCHG/call encodings replace xbyak emission; there are no new dependencies. Both jump-table recognizers, the validated sweep, forward/backward spans, spare-padding relays, nearby relocated relay hosts and short-relay chains are ported. Resolved indirect targets are explicit successors in the liveness graph. The local operand classifier proves byte uses/definitions for scalar MOV forms. Other red-zone operands, possible RSP register aliases and any nonzero stack delta force conservative liveness; the latter avoids dropping values temporarily above RSP in existing TLS/AMD stubs. The pass follows `.gtcode` and `.amdstub` jump stubs created earlier in PE generation, because those stubs may contain relocated faulting neighbors.
  A direct call selected only by conservative liveness is counted as unrelocatable and kept on its original stack, since lowering a genuine call would change its stack arguments. The register-write classifier may reject jump-table proofs across instructions whose GPR effects it cannot establish. Table pointers must use 64-bit LEA, MOVSXD, ADD and register-copy forms; indexed table loads with segment overrides, 32-bit addresses or nonzero displacements are unsupported. Remaining indirect functions use Kyty's validated sweep with conservative liveness and prohibit neighbor relocation. Explicit vector register fields that might name RSP are conservatively refused; this can overcount stack dependencies for XMM4. Those refused sites stay unprotected, and in Demon's Souls (PPSA01341) 705 of the executable's 2516 stack-dependent memory instructions were XMM4/YMM4 or VEX.vvvv=4 loads and stores. `ANYPS5_RELINK_REDZONE_VECTOR_REGISTERS=1` (exact value, only with `ANYPS5_RELINK_REDZONE=1`) classifies the ModRM reg and r/m fields and VEX.vvvv per opcode map instead: legacy SSE/MMX opcodes and VEX maps 0F, 0F38 and 0F3A name vector registers there, except the general-purpose fields of CVT*2SI, MOVMSK, PEXTRW, PMOVMSKB, MOVD/MOVQ, CVTSI2S*, PINSR*, PEXTR*, MOVNTI, the 0F38/0F3A F0-FF block (MOVBE, CRC32, BMI1/BMI2, RORX), MMX/SSE opcodes 78/79 and every XOP or EVEX form, which keep the conservative rule. It then patches those 705 sites, and lists each remaining stack-dependent site as `reason=stack-dependent` (in that game, register PUSH/POP only). Unset or other values keep the conservative classifier and its PE bytes. Partial SP writes and spans overlapping PE base relocations or runtime import/TLS fixups are refused, as preserving the original upper RSP bits and moving relocation records are not implemented. Missing function tables are counted, malformed or unsupported tables fail relinking, and indirect DWARF pointer encodings and LEB128 table encodings are unsupported. Functions without unwind starts are not discovered. The counters mirror all twelve Kyty fields and add refused-function and missing-table counts; `patched` includes protected direct calls as in Kyty. Nonzero refusal counters and missing metadata mean coverage is incomplete. The `relinker_redzone` ctest variants (red zone on, off, vector registers on, non-exact and without the red-zone pass) cover enabled/disabled byte identity, results and flags, RIP relocation, calls, jump-table proofs, a short relay, existing AMD stubs and actual Windows exception canaries. Stores fault on `PAGE_READONLY`; loads use `PAGE_NOACCESS`, since read-only pages permit loads. An off-mode fault test skips with code 77 if Windows preserves all original canaries. On Windows 11 26200 without AVX-512 it preserves them only while the upper YMM halves are in their initial state: delivery then writes from RSP-312 downwards, but with dirty upper halves the saved AVX state reaches RSP-56, so game code (which keeps YMM state dirty) loses red-zone bytes on every unprotected fault. The `fault-vector-store` variants dirty YMM4 and store it with VMOVDQU; they show the corruption with the switch off and require intact canaries with `ANYPS5_RELINK_REDZONE_VECTOR_REGISTERS=1`. Synthetic tests do not establish the G3 game-validation gate, instruction-fetch faults, arbitrary alias-based stack access, C++ unwinding through the generated stubs, or compatibility with every decoder-supported opcode. Broad page tracking still needs the integrator's module-counter review and canary/game validation.
- [Runtime-loaded modules](../../../core/relinker/relinker/src/guest/GuestModuleBuilder.cpp) (`--module-dir`) that another module needs are initialized at startup with no start arguments, before the module that needs them is loaded; the console is assumed to start them when that module is loaded.
- The executable file that [relinker](../../../core/relinker/elfpatcher/src/windows/WindowsPeWriter.cpp) generates opens a console when launched, unless it is relinked with `--windows-gui`, which selects the GUI subsystem. A GUI build started from Explorer has no standard output or error handle, so everything it prints is lost, including the entry stub's errors and crash reports (#3282).
- [SDK memory-management syscall traps](../../../core/relinker/relinker/src/analysis/SyscallScanner.cpp) under `--trap-sdk-syscall-stubs` recognize three exact instruction sequences from [ps5-payload-dev SDK libc/mman.c](https://github.com/ps5-payload-dev/sdk/blob/12cf3dda40/libc/mman.c), observed in Nuvio Maxd 0.5.15 (PPSA99288): syscall 74 and the two syscall 477 paths, with their argument preparation and carry-flag error handling. Matching requires a decoded instruction boundary and the complete sequence inside the scanned code range. Other SDK/compiler output remains rejected. The matched syscall becomes `UD2`; this does not implement mmap or mprotect and a call still faults.
- `--to-intel` does not lower RDPRU/MCOMMIT; the [matcher](../../../core/relinker/codegen/src/x86/Amd64OnlyInstructionMatcher.cpp) fails the relink instead.
- The length-changing path of the [instruction rewriter](../../../core/relinker/codegen/src/x86/X64InstructionRewriter.cpp) is not used by the [converter](../../../core/relinker/codegen/src/Amd64OnlyConverter.cpp): it does not adjust data-to-code references (relocations, FDEs, jump tables) or segment sizes, so every substitution keeps the instruction length.
- A `PT_SCE_RELRO` segment that no `PT_LOAD` covers, the PS4 layout, is [loaded](../../../core/relinker/relinker/src/parsing/ElfReader.cpp) as a read-write `PT_LOAD` and stays writable after relocation; FreeBSD rtld makes `PT_GNU_RELRO` read-only once relocation is done, and what the console does with `PT_SCE_RELRO` is not checked. The `unused-filter=1` and `unused-filter=2` readers parse the program headers themselves and do not load it.
- In executables with a `PT_SCE_DYNLIBDATA` segment, the PS4 layout, the executable segment also holds read-only data after the code (CUSA00900: 37 MiB after its last function). The [relinker pipeline](../../../core/relinker/relinker/src/pipeline/RelinkerPipeline.cpp) therefore scans for syscalls and import call sites only up to the end of the PLT that follows the last function of the unwind table; code after the PLT without an unwind entry is not scanned. `--to-intel` and the `unused-filter=1` and `unused-filter=2` analyses are not limited this way.
- A relocation against a dynamic symbol entry that is all zero, like the null symbol, takes the value 0 plus its addend, as the gABI defines for `STN_UNDEF` ([pipeline](../../../core/relinker/relinker/src/pipeline/RelinkerPipeline.cpp)). The Linux output imports such an entry as an unnamed weak symbol, which the host loader resolves to 0; the Windows and macOS outputs write the value into the slot ([relocation builder](../../../core/relinker/elfpatcher/src/windows/WindowsRelocationBuilder.cpp)). What the console's loader does with such an entry is not measured. OliSe Player (PPSA01153) has seven of them, and its code calls through those slots only when they are not 0 ([#4437](https://github.com/boykopovar/AnyPS5/issues/4437)).
- The Linux placement of the `--to-intel` stubs in the [ELF patcher](../../../core/relinker/elfpatcher/src/linux/LinuxElfPatcher.cpp) is covered only by a synthetic test.
- `--to-rosetta` lowers what Rosetta lacks on top of `--to-intel` ([matcher](../../../core/relinker/codegen/src/x86/Amd64OnlyInstructionMatcher.cpp)). Rosetta runs AVX2, FMA, BMI1/2, F16C and MOVBE but reports none of them through CPUID, so code that checks CPUID takes its baseline path. RDSEED becomes RDRAND and CLWB a NOP. RDPID returns processor 0, because Rosetta's TSC_AUX is the constant 0xAAAAAAAB; the same value reaches RDTSCP's ECX, which is not converted. ADCX/ADOX fault under Rosetta and are not converted: compilers do not emit them, and code that checks CPUID sees no ADX. The conversions are covered by the converter tests; that the converted code runs under Rosetta was checked on an M5 Max only, outside this repository's CI.
- `--to-intel` replaces the approximate legacy SSE and VEX.128 register forms of RSQRTPS/RCPPS and VRSQRTPS/VRCPPS with [correctly rounded](../../../core/relinker/codegen/src/x86/ReciprocalLowering.cpp) 1/sqrt(x) and 1/x, not with the AMD approximation: its tables are not public. Intel's approximation of 1/sqrt(1.0) is 0x3F7FF000, and two Newton-Raphson steps on it settle on 0.99999994 instead of 1.0; a renormalised identity quaternion then turns into a NaN axis in PPSA21564, which the console does not show. Refined results now reach the exact value; unrefined ones can still differ from the console in the low bits. Each site costs an out-of-line stub (two jumps, a spill below the red zone, SQRTPS/DIVPS). Legacy SSE forms preserve the destination's upper YMM bits; VEX forms clear them. The 256-bit, scalar and memory forms keep the native instruction, as does a site shorter than 5 bytes with no movable instruction after it for the jump (5 sites in PPSA21564, counted before a following RIP-relative instruction could move into the stub; not recounted).
- `--trace-imports` ([entry stub](../../../core/relinker/elfpatcher/src/windows/WindowsEntryStubBuilder.cpp)) exists for Windows output only. Only imports bound through a PLT slot, or through a GOT slot whose symbol is a function, are traced; a function reached through any other relocation, or looked up at run time with `sceKernelDlsym`, is not, and neither are weak imports or the imports of modules loaded at run time
